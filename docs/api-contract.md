# Contrato interno da API v1

Prefixo `/api`. O frontend usa `/api/*` na mesma origem, encaminhado a `API_INTERNAL_URL` (padrão http://localhost:4100). API porta 4100; web 3100. Datas de negócio YYYY-MM-DD, valores decimais serializados como strings. IDs UUID. Sem autenticação. Erros `{message: string | string[], fieldErrors?: Record<string,string>, missingFields?: string[]}`. Erros de campo retornam400, com chaves do payload; itens usam `items.<índice>.campo`. GET /health retorna `{status:'ok', database:'ok'}` com verificação do banco.

## Contratos
Somente leitura da réplica diária do Contratos.gov.br (`public_sources.contracts`); a API nunca consulta a origem. Contratos são identificados pelo id externo do Contratos.gov.br (`:externalId`, inteiro positivo de até 19 dígitos dentro de bigint). Só aparecem contratos cuja UG gestora é a UASG de uma instituição cadastrada, inclusive para o gestor geral; fora do escopo, não cadastrado ou id inválido retorna 404 `Contrato não encontrado.`. Todas as respostas usam `Cache-Control: no-store`. CPF de fornecedor (11 dígitos) sai mascarado `***.DDD.DDD-**` e não é pesquisável; CNPJ sai em dígitos.
`GET /contracts?search=&status=&uasg=&from=&to=&uasgs=&page=1&limit=12` retorna `{data: ContractSummary[], total, page, limit, stats:{count,totalValue,expiringCount,vigency:{active,expiring,ended,upcoming,unknown,activeValue}}, sync:{lastCompletedAt,running,staleUnits:[{uasg,name,lastGoodAt}]}}`; stats sobre o filtro todo; ordem `endDate` decrescente (sem data por último). Status: UPCOMING, ACTIVE, EXPIRING, EXPIRED, UNKNOWN. Janela vencendo 30 dias; UTC por dia de calendário. Filtro de período por interseção da vigência, incluindo datas iguais; datas desconhecidas só aparecem sem filtro de período. `sync.lastCompletedAt` é o fim da última execução diária concluída; `staleUnits` lista as UASGs do escopo cuja última listagem válida é anterior ao início dessa execução (vazio antes da primeira execução concluída).
ContractSummary: `{externalId,number,object,supplierName,supplierDocument,uasg,unitName,startDate,endDate,globalValue,status}`.
`GET /contracts/:externalId` retorna `{contract, parts, notes}`: `contract` = ContractSummary + `{originUnitCode,typeName,category,processNumber,modality,sourceStatus,signatureDate,initialValue,accumulatedValue,installmentCount,capturedAt,normalizedAt}`; `parts` = `{part,status:'AVAILABLE'|'NOT_FOUND'|'FAILED'|'MISSING',capturedAt,lastAttemptAt,rowCount}[]`; `notes` = `{text,updatedAt,updatedBy}`.
`GET /contracts/:externalId/source/:part?page=&limit=` (`history|guarantees|responsibles|items|invoices|files`) retorna `{data,total,page,limit}`; limite padrão 20, máximo 100.
`GET /contracts/:externalId/commitments` retorna os empenhos que o Contratos.gov.br informa para o contrato, ligados à execução financeira importada pelo código do Portal da Transparência (`transparencyCode` = UG + gestão + número = `finance.commitment_references.document_code`), com o mesmo 404 da ficha: `{commitments: CommitmentLink[], campuses: CampusTotals[], totals: Amounts & {count}, balance:{globalValue,remaining}}`. Amounts: `{committed,liquidated,paid,rpRegistered,rpToLiquidate,rpLiquidated,rpPaid}`, sempre os valores do Contratos.gov.br; uma soma é `null` quando qualquer parcela é `null`. CommitmentLink: Amounts + `{transparencyCode,number,unitCode,unitName,issueDate,creditor,expenseNature,financeStatus,financeCommitmentId,financeCommitted,lastImportedOn,linkable}`. `financeStatus`: `CONFIRMED` (referência existe na execução financeira, com ou sem cabeçalho importado), `NOT_FOUND` (o dia de emissão foi importado com sucesso, ou a data é desconhecida, e o empenho não veio), `PENDING` (emissão posterior à última importação da UG ou em dia não importado; `lastImportedOn` = último dia importado), `OUT_OF_SCOPE` (nenhuma importação diária bem-sucedida cobre a UG, ou emissão anterior ao primeiro dia importado). Cobertura = `finance.ingestion_runs` `DAILY_EXPENSES`/`SUCCESS` com escopo `MANAGEMENT` (gestão) ou `MANAGEMENT_UNIT` (UG). `financeCommitted` é o empenhado da execução financeira (soma dos itens atuais), só quando há cabeçalho. `linkable` indica que o detalhe financeiro está no escopo do usuário. `campuses` agrupa por UG emitente (`unitName` cai para o código), ordenado por nome; `balance.remaining` = valor global menos total empenhado.
`PUT /contracts/:externalId/notes` body `{notes: string}` grava as observações internas (texto aparado, até 10.000 caracteres; vazio limpa) com autor e data e retorna `notes`. É o único dado de contrato gravado pela aplicação e sobrevive às execuções diárias.

## Atas
`GET /records?search=&page=1&limit=12` retorna `{data: PriceRecord[],total,page,limit,stats:{count,totalValue,exportsCount}}`. `GET /records/:id` inclui itens e exports; `POST /records`, `PUT /records/:id`, `DELETE /records/:id`.
PriceRecord: `{id,number,processNumber,purchaseNumber,purchaseYear,modality:'PREGAO'|'DISPENSA',object,startDate,endDate,renewable,uasg,organizationName,organizationDocument,organizationStreet,organizationNumber,organizationCity,organizationState,authorityName,authorityRole,authorityRegistration,ordinanceNumber,ordinanceDate,ordinancePublicationDate,supplierName,supplierDocument,supplierRepresentative,items,createdAt,updatedAt,totalValue,exports?}`. Campos cadastrais strings default '', datas null, renewable false, purchaseYear inteiro opcional. Rascunho pode conter só number+object+uasg, campos para exportar validados separadamente. Items: `{id?,number:number,description,brand,model,unit,quantity,minimumQuantity,unitPrice,warranty}`; quantity/minimumQuantity/unitPrice decimais string >=0; minimumQuantity<=quantity. Item number único por documento. A identidade local é número+UASG+fornecedor; documentos de fornecedores distintos podem manter o mesmo número oficial da ata. Campos de origem `sourcePublicRecordId` e `sourceSupplierDocument` são somente leitura pelo editor e sustentam a preparação idempotente pelo catálogo. POST/PUT items substitui conjunto atomicamente; PUT preserva histórico de exportações. Valores nunca binary float em cálculos.
`POST /records/import` body `{uasg,number,from,to}` retorna PriceRecord importada. Identidade já existente retorna 409 e preserva campos e itens locais; não há substituição por reimportação. Datas from/to restringem busca pública; fornecedor único por ata/documento; rejeitar resposta com vários fornecedores (422), nunca escolher primeiro silenciosamente. Campos ausentes importados como rascunho editável.
`GET /records/:id/readiness?itemId=` retorna `{ready:boolean,missingFields:string[]}`. Obrigatórios: number,processNumber,purchaseNumber,object,organizationName,organizationDocument,organizationStreet,organizationCity,organizationState,authorityName,authorityRole,supplierName,supplierDocument e ao menos um item com descrição,unidade,quantidade>0 e preço>0. Validação consistente export/readiness.
`GET /records/:id/document?format=docx|pdf&itemId=` download arquivo binário com Content-Disposition. Registra export somente após geração bem sucedida. Exporta com modelo arp-ata-14133.docx original adaptado. Sem Gotenberg DOCX continua disponível. PDF timeout retorna 503 mensagem útil. Export snapshot imutável JSON salva dados e itemId, formato e templateVersion. `GET /records/:id/exports` retorna `{id,format,templateVersion,createdAt,itemNumber?}[]`.

## Regras de entrada e apresentação (31/10/2026)

- Identificação de fornecedor: CPF de11 dígitos ou CNPJ de14 posições, com dígitos verificadores corretos. CNPJ aceita letras A-Z nas12 primeiras posições, preservadas em maiúsculas conforme o formato da Receita Federal. Organização exige CNPJ. Máscaras `000.000.000-00` / `00.000.000/0000-00` são apresentação; API normaliza pontuação conhecida e valida também entradas diretas.
- UASG é string com exatamente6 dígitos, inclusive zeros iniciais. UF é sigla válida entre as27 unidades federativas, normalizada em maiúsculas.
- Decimais possuem até18 dígitos inteiros e6 fracionários, não negativos; UI aceita colagem brasileira como `R$1.234,567890` e decimal canônico. Nenhum parser remove sinal negativo para tornar um valor positivo nem trunca casas excedentes. Valores enviados/armazenados continuam decimais canônicos string. Valores unitários na tela e no Word preservam casas significativas até6.
- Datas são dias reais AAAA-MM-DD; fim não pode anteceder início. Aplicar também a filtros e importações.
- Número da ata/compra/processo aceita formatos institucionais variados, com validação de texto/tamanho, sem impor NUP a todos.
- Rascunhos continuam aceitando campos opcionais vazios. Quando preenchidos, precisam ser válidos; documentos legados inválidos devem ser corrigidos antes da exportação.
- Interface valida no blur e no envio, mostra resumo e erros ao lado dos campos, associa aria-describedby e focaliza o primeiro campo inválido. Falha de carregamento nunca libera formulário vazio para substituir um registro existente.
